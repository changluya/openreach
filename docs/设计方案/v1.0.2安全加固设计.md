# OpenReach v1.0.2 安全加固设计

> 目标：把 OpenReach 明确收敛成“三个 JSON API + 只读官网静态资源”的最小公网攻击面，禁止上传/写文件，并强化所有用户可控远程 URL 的 SSRF 防护。

## 1. 公网 Allowlist

业务 API 只有：

```text
POST /api/web/search
POST /api/web/image-search
POST /api/web/read
```

只读网站资源：

```text
/
/index.html
/docs[/]
/docs/index.html
/docs/api.html
/community[/]
/assets/**
/downloads/openreach-skill.zip
```

其他路径默认 `404`，避免未来误加 Controller、Actuator 或调试端点后自动暴露。

## 2. 上传与文件植入防护

应用不提供任何上传/保存文件业务。双层关闭：

1. `AttackSurfaceFilter` 拒绝所有 `multipart/*`；
2. `spring.servlet.multipart.enabled=false`；
3. API 只接受 `application/json`；
4. 静态资源只来自 `classpath:/static/`，不映射宿主文件目录；
5. Docker 部署继续采用非 root、只读根文件系统、`no-new-privileges`、`cap_drop: ALL`。

因此用户无法通过 HTTP 请求把任意文件写入官网目录或应用工作目录。

## 3. HTTP 方法与请求体

- API：仅 POST；
- 静态资源：仅 GET/HEAD；
- PUT/PATCH/DELETE/TRACE 等拒绝；
- API Body 默认最大 64 KiB；
- 同时检查 Content-Length 和真实流读取，避免 chunked 绕过；
- Query / URL / region / provider / timeRange 继续由 Bean Validation 与业务解析限制。

## 4. Path Traversal

Filter 在 Dispatcher 前拒绝：

```text
..
反斜线
分号 path parameter
任意 percent-encoded path
控制字符
```

静态资源又只允许固定路径和 `/assets/**`，形成 allowlist + classpath 双重边界。

## 5. Read / Image SSRF

`UrlSafetyGuard` 是用户 URL 和图片候选 URL 的统一安全边界：

- 只允许 HTTP/HTTPS；
- 只允许 80/443；
- 禁止 user-info；
- 禁止 localhost、`.local`、`.internal`、云元数据主机；
- DNS 解析结果禁止 loopback、RFC1918、link-local、CGNAT、benchmark、TEST-NET、multicast、IPv6 ULA/文档段等；
- 每次重定向重新校验目标；
- Read 限制 redirect/body；Image Probe 限制 redirect/timeout/read prefix。

> 应用层 DNS 校验无法替代网络层出口控制。生产环境仍建议用容器/防火墙 egress ACL 禁止访问 RFC1918、link-local 和云元数据网段，形成纵深防御。

## 6. 图片内容安全

Image Search 返回前只读取小段原图字节用于验证：

- HTTP 2xx；
- 拒绝 text/html/xml；
- 明确拒绝 SVG 主动内容；
- 只接受 JPEG/PNG/GIF/WebP/BMP/TIFF/ICO/AVIF/HEIC 等已知被动图片签名；
- 不执行脚本、不解析图片元数据、不保存文件。

## 7. 官网浏览器安全

统一响应头：

```text
Content-Security-Policy
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer
Permissions-Policy
Cross-Origin-Opener-Policy
Cross-Origin-Resource-Policy
```

官网主题初始化脚本已从 inline script 移为 `/assets/theme-init.js`，使 `script-src 'self'` 无需 `unsafe-inline`。

## 8. 上游资源上限

搜索页和图片搜索 Provider 的 HTML / JSON 不再使用无界 `ofByteArray()`：

- Web Search 上游响应默认最大 2 MiB；
- Image Search Provider 上游响应默认最大 4 MiB；
- 同时检查 `Content-Length` 和流式真实读取大小；
- 超限立即关闭响应流并作为当前 Provider 失败处理；
- Read 原有 `max-bytes` 边界继续保留；
- Image Probe 只读取小段文件头，不下载完整图片到服务端；
- Probe Executor 使用固定并发 + 有界队列（默认 48）+ CallerRuns 背压，避免公网高并发把验证任务无界堆入内存。

这使三个能力都具备明确的上游内存边界，避免异常 Provider 响应造成 JVM 无界分配。

## 9. 依赖安全基线

当前 `pom.xml` 使用 Spring Boot `4.1.0`。Spring Boot 4.1.0 官方 Release Notes 明确将 Spring Framework 升级至 `7.0.8`；Spring 官方 CVE-2026-41843 公告中，`7.0.8` 也是该静态资源路径穿越问题的 OSS 修复版本。

工程仍额外采用 `classpath:/static/` + `AttackSurfaceFilter` 路径 allowlist，不依赖框架修复作为唯一边界。发布时仍建议执行 `mvn dependency:tree` 与依赖漏洞扫描，确认实际解析依赖未被外部 BOM/父工程覆盖。

## 10. 错误信息

- 参数错误返回可操作的客户端错误；
- 未知服务端异常只在服务端日志保留细节；
- 客户端统一收到泛化 `Internal server error`，避免堆栈/实现细节泄露。

## 11. 必测安全 Case

```text
仅三个 API 能进入应用链
/api/web/health -> 404
/actuator/* -> 404
/upload / /api/upload -> 404
multipart -> 415 UPLOAD_DISABLED
非预期 Method -> 405
超大 Body -> 413
../ / encoded traversal -> 400
静态官网包含 CSP 等安全 Header
localhost / metadata / private / CGNAT / TEST-NET -> SSRF reject
图片 Probe 对 localhost -> false
HTML/SVG/随机字节 -> 非图片
Search/Image Provider 超大上游 Body -> 拒绝
```

## 12. 明确不承诺

OpenReach v1.0.2 不把“安全”描述为绝对无漏洞。应用层已把当前已知公网攻击面最小化，但生产环境仍应持续做依赖漏洞扫描、镜像升级、WAF/限流、出口 ACL、日志告警与版本升级。
