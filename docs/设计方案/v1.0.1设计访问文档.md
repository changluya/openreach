# OpenReach v1.0.1 设计访问文档

> 版本：**v1.0.1**  
> 定位：OpenReach 首个正式维护基线  
> 文档职责：统一收敛原《初版本设计方案》《当前工程能力与渠道支持》《核心测试与验收》中属于 v1.0.1 的设计、渠道、测试与验收口径。  
> 后续版本：v0.1.2 的海外路由、安全加固、时间范围和图片可下载门禁统一见 [`v0.1.2优化（安全+海外）文档.md`](v0.1.2优化（安全+海外）文档.md)。

## 1. 版本定位

OpenReach v1.0.1 面向 AI Agent 提供一组尽可能简单、稳定、可扩展的 Web 访问原语：

```text
search(query)        -> 发现网页与信息源
image-search(query)  -> 发现图片
read(url)            -> 读取网页正文
```

核心目标不是建设一个新的搜索引擎，而是在 Agent 与公网搜索/网页之间提供统一基础设施层：

```text
AI Agent / AgentHub / Coding Agent
              │
              ▼
         OpenReach HTTP API
              │
      ┌───────┼────────┐
      ▼       ▼        ▼
   Search   Image     Read
      │       │        │
      ▼       ▼        ▼
 Provider   Provider  PageReader
  Chain      Chain      SPI
      │       │        │
      └───────┴────────┘
              │
              ▼
           Public Web
```

v1.0.1 优先解决国内开发、自托管和轻量 Agent 联网场景，默认不依赖 Serper、Tavily 等商业 Search API Key。

## 2. 核心设计原则

### 2.1 三个稳定原语，上层不感知渠道差异

Agent 只需要理解 Search / Image Search / Read，不需要知道底层是 Bing、百度、搜狗还是 Openverse。

### 2.2 Provider SPI 解耦

三类能力分别通过独立扩展接口承载：

```text
SearchProvider
ImageSearchProvider
PageReader
```

新增渠道时优先实现 Provider，而不是修改 Controller 或上层 Agent 协议。

### 2.3 免费渠道优先 + 自动降级

`provider=auto` 按配置顺序尝试 Provider。单路出现超时、解析失败或空结果时继续后续渠道，避免 Agent 直接绑定单一上游。

### 2.4 Read 安全优先

用户输入 URL 属于不可信输入。Read 通过 `UrlSafetyGuard + SafeHttpFetcher` 做 SSRF、重定向和响应大小控制，不允许把 OpenReach 变成内网探测器或任意代理。

### 2.5 v1.0.1 保持轻量

首版只覆盖通用 Web 发现与读取，不引入账号池、代理池、验证码绕过、复杂浏览器集群或商业 Search 依赖。

## 3. 总体架构

```text
┌──────────────────────────────────────────────┐
│              AI Agent / Client               │
└──────────────────────┬───────────────────────┘
                       │ HTTP + JSON
                       ▼
┌──────────────────────────────────────────────┐
│                 OpenReach                    │
│                                              │
│  /api/web/search                             │
│       │                                      │
│       ▼                                      │
│  SearchService ──> SearchProvider Chain      │
│                                              │
│  /api/web/image-search                       │
│       │                                      │
│       ▼                                      │
│  ImageSearchService -> ImageProvider Chain   │
│                                              │
│  /api/web/read                               │
│       │                                      │
│       ▼                                      │
│  WebReadService -> PageReader -> Safe HTTP   │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
                 Public Internet
```

Service 层统一负责：

```text
参数校验
-> Provider 选择
-> fallback
-> merge / dedupe
-> rank / limit
-> 统一 DTO
```

Provider 负责：

```text
构造上游请求
-> 解析上游响应
-> 映射统一结果模型
```

## 4. HTTP API

### 4.1 Web Search

```text
POST /api/web/search
Content-Type: application/json
```

典型请求：

```json
{
  "query": "Spring Boot AI Agent",
  "limit": 5,
  "region": "CN",
  "provider": "auto"
}
```

核心字段：

| 字段 | 说明 |
|---|---|
| `query` | 搜索关键词 |
| `limit` | 返回结果数量 |
| `region` | 地区/Locale Hint；v1.0.1 尚未用于 CN/GLOBAL 核心路由 |
| `provider` | `auto` 或显式 Provider |

统一输出重点包括：标题、URL、摘要、来源域名、Provider、Rank。

### 4.2 Image Search

```text
POST /api/web/image-search
Content-Type: application/json
```

典型请求：

```json
{
  "query": "杭州西湖夜景",
  "limit": 8,
  "region": "CN",
  "provider": "auto"
}
```

统一结果模型重点包括：

```text
imageUrl        原图地址
thumbnailUrl    缩略图地址
sourcePageUrl   来源页面
source/domain   来源信息
width/height    图片尺寸（上游可提供时）
format          图片格式（上游可提供时）
license         授权信息（上游可提供时）
licenseUrl      授权说明地址（上游可提供时）
provider        实际命中的 Provider
rank            统一排序
```

Image Search 独立于 Web Search 的原因：图片搜索结果模型、上游协议、去重方式和后续可下载性验证都与普通网页搜索不同，不应该用一个通用 Search DTO 强行承载。

### 4.3 Web Read

```text
POST /api/web/read
Content-Type: application/json
```

典型请求：

```json
{
  "url": "https://spring.io/projects/spring-boot",
  "maxChars": 20000
}
```

核心输出：

```text
url / finalUrl
title
content
contentType
reader
truncated
metadata
links
latencyMs
```

## 5. v1.0.1 已对接渠道

### 5.1 Web Search

默认链：

```text
bing -> baidu -> sogou -> so360 -> duckduckgo
```

| Provider | 标识 | 定位 | 接入方式 |
|---|---|---|---|
| Bing 中国 | `bing` | 默认第一路 | 公开搜索结果页 best-effort 解析 |
| 百度 | `baidu` | 中文核心 fallback | 公开搜索结果页 best-effort 解析 |
| 搜狗 | `sogou` | 国内 fallback | 公开搜索结果页 best-effort 解析 |
| 360 搜索 | `so360` | 国内 fallback | 公开搜索结果页 best-effort 解析 |
| DuckDuckGo | `duckduckgo` | 海外兜底 | HTML Search 页面解析 |

v1.0.1 的 `region` 主要作为 Provider Hint；自动搜索仍使用单一全局 Provider Chain。这也是 v0.1.2 增加 CN / GLOBAL 双路由的直接原因。

### 5.2 Image Search

默认链：

```text
bing -> baidu -> sogou -> openverse
```

| Provider | 标识 | 定位 | 接入方式 |
|---|---|---|---|
| Bing Images | `bing` | 默认第一路 | 页面/异步结果解析 |
| 百度图片 | `baidu` | 中文图片核心 fallback | `acjson` + Cookie warmup |
| 搜狗图片 | `sogou` | 国内 fallback | 页面初始化状态解析 |
| Openverse | `openverse` | 开放许可图片补充源 | 官方公开 API |

v1.0.1 负责“发现图片 URL”，尚未承诺每一条原图 URL 在返回时一定可下载；该质量门禁在 v0.1.2 才补齐。

### 5.3 Web Read

Read 不依赖外部搜索 Provider，核心链：

```text
WebReadService
  -> PageReader SPI
  -> JsoupPageReader
  -> SafeHttpFetcher
  -> UrlSafetyGuard
  -> HtmlContentExtractor
```

适用于公开 HTML / SSR 页面。JavaScript 强依赖页面、PDF、Office 等不属于 v1.0.1 主能力。

## 6. Provider SPI 设计

### 6.1 SearchProvider

Provider 对外只暴露“是否支持”和“执行搜索”能力；SearchService 负责 fallback、聚合与去重。

设计目标：

```text
新增 Provider
  -> 新增实现类
  -> 注册 Bean
  -> 加入 provider-order
  -> 增加 Fixture 单测
```

避免把不同网站 Parser 写进 Service。

### 6.2 ImageSearchProvider

Image Search 保持独立 SPI，允许 Provider 输出图片特有字段，并为后续 License、图片质量、下载验证等能力留扩展空间。

### 6.3 PageReader

Read 使用独立 `PageReader` SPI。v1.0.1 默认 `JsoupPageReader`，未来可增加 Browser Reader、PDF Reader 或远端 Reader，而不改变 `/api/web/read` 协议。

## 7. 自动降级与聚合

`provider=auto` 的基本流程：

```text
Provider Order
   │
   ▼
Provider #1
   ├─ 成功且有结果 -> 接收
   └─ 失败/空结果  -> Provider #2
                         │
                         └─ ...
```

聚合阶段执行：

```text
结果标准化
-> URL/图片去重
-> 统一 rank
-> limit 截断
```

显式 Provider 用于诊断和可控调用，不进入自动 fallback 链。

## 8. Read 与 SSRF 安全边界

`UrlSafetyGuard` 是 v1.0.1 的核心安全组件，主要保护：

- 非 HTTP/HTTPS Scheme；
- localhost / loopback；
- RFC1918 私网地址；
- DNS 解析后的内网地址；
- Redirect 后重新校验；
- 最大 Redirect 次数；
- 最大响应体；
- 请求超时。

基本原则：

```text
用户 URL
  -> 语法校验
  -> Host/DNS 校验
  -> 发起请求
  -> 每次 Redirect 再校验
  -> 有界读取
  -> 正文抽取
```

v1.0.1 已具备 Read 侧 SSRF 基线，但尚未像 v0.1.2 一样把整个公网攻击面收敛到统一 HTTP Allowlist。

## 11. v1.0.1 测试与验收基线

### 11.1 验收硬规则

正式 Release Gate：

```bash
mvn clean test
```

必须满足：

```text
Failures = 0
Errors   = 0
BUILD SUCCESS
```

Provider 的真实公网可用性不放进稳定 JUnit，避免网络波动导致 CI Random Fail；真实渠道通过独立 Smoke Test 验证。

### 11.2 当时测试规模

v1.0.1 正式维护基线记录：

```text
Java @Test               38
OpenReach Skill Python    5
合计                     43
```

Java 重点覆盖：

- Spring Context；
- Region 默认行为；
- 官网 / 静态资源；
- Health API；
- Web Search Provider Parser；
- SearchService fallback / 聚合 / 去重 / 显式 Provider；
- Image Search Provider Parser；
- ImageSearchService fallback / 去重 / 显式 Provider；
- HTML 正文提取；
- SSRF 核心边界。

Skill Python 测试重点覆盖配置、初始化和基本 CLI 行为。

### 11.3 Provider Parser 测试原则

每个基于公开页面解析的 Provider 应保存最小 Fixture，至少验证：

```text
正常结果
关键字段映射
空结果
异常结构容错
广告/内部链接过滤（适用时）
```

禁止把公网实时请求当作单元测试事实源。

### 11.4 Service 测试原则

Search / Image Service 必测：

```text
默认 Provider Chain
首路失败后 fallback
空结果 fallback
显式 Provider
未知 Provider
去重
limit
rank
```

### 11.5 Read / SSRF 回归

至少覆盖：

```text
公开 HTTP/HTTPS URL
localhost 拒绝
私网地址拒绝
DNS 解析后私网拒绝
Redirect 复检
响应大小限制
正文抽取
maxChars 截断
```

### 11.6 Smoke Test

发布前至少手工验证：

```text
Web Search Auto
Web Search 显式 Provider
Image Search Auto
Image Search 显式 Provider
Read
Health
官网 /docs/
```

免费公开搜索页面属于 best-effort，某一 Provider 临时 403/429/CAPTCHA 不代表工程单测失败，但 Auto Chain 在目标部署网络中应至少存在可工作的默认路径。

## 12. v1.0.1 能力边界

明确不承诺：

- 商业级 Search SLA；
- Search Pagination；
- 跨 Provider Freshness 统一；
- 商业级精准 Geo；
- Shopping / Places / Knowledge Graph；
- JavaScript 动态页面 Browser Read；
- PDF / Office Reader；
- 高 QPS Search API；
- 账号池 / 代理池 / CAPTCHA 绕过；
- Image 原图实时可下载保证；
- CN / GLOBAL 独立 Provider Chain。

## 13. 从 v1.0.1 到 v0.1.2

v1.0.1 证明了“三大原语 + Provider SPI + fallback”的核心结构可行。v0.1.2 在不修改三大 API 主路径的前提下重点补齐：

```text
CN / GLOBAL Route
海外零 Key Web/Image Provider Chain
Search timeRange
Image 原图可下载质量门禁
统一公网 Attack Surface Allowlist
更完整的 SSRF / Body / Browser Header 安全边界
```

## 14. v1.0.1 最终结论

v1.0.1 的核心价值不是 Provider 数量，而是把 Agent 的公网访问能力收敛成了稳定的三层模型：

```text
统一 HTTP 原语
    ↓
可插拔 Provider / Reader SPI
    ↓
免费渠道 fallback + 安全读取
```

这套基线为 v0.1.2 的海外路由和安全强化提供了稳定演进基础。
