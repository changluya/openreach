# OpenReach v1.0.2 设计落地方案

> 基线版本：**v1.0.1**  
> 当前版本：**v1.0.2**  
> 状态：**已落地实现**  
> 核心目标：在不破坏 v1.0.1 国内免费渠道能力的前提下，新增可扩展的 **CN / GLOBAL 双路由**，补齐高质量、零 API Key 的海外搜索能力。

---

## 1. v1.0.2 解决什么问题

v1.0.1 已经具备：

```text
search(query)
image-search(query)
read(url)
```

并完成国内优先的多 Provider fallback。但 v1.0.1 的自动搜索只有一条全局 `provider-order`：

```text
bing -> baidu -> sogou -> so360 -> duckduckgo
```

即使请求明确传：

```json
{"query":"latest Java Agent frameworks","region":"US","provider":"auto"}
```

Service 仍然先走国内链，`region` 只是透传给 Provider，没有真正参与核心路由。

v1.0.2 将它改造为：

```text
region
  ↓
SearchRouteResolver
  ↓
ProviderChainResolver
  ├─ CN      -> 国内免费 Provider Chain
  └─ GLOBAL  -> 海外免费 Provider Chain
```

接口 DTO 不增加新字段，继续复用已有 `region`，因此对 AgentHub Plugin、Skill、已有调用方保持兼容。

## 2. v1.0.1 → v1.0.2 能力差异

| 能力 | v1.0.1 | v1.0.2 |
|---|---|---|
| Search 自动路由 | 单一 Provider Chain | **CN / GLOBAL 双链** |
| `region` | Provider best-effort Hint | **先决定核心 Route，再作为 Locale Hint 透传** |
| 默认 `region=auto` | 国内优先 | **仍为国内优先，兼容旧行为** |
| 海外 Web Search | DDG 兜底 | **Brave → DuckDuckGo → Bing Global** |
| Bing | 固定 `cn.bing.com` | **CN / Global Host 自动选择** |
| DuckDuckGo | GET 拼参数 | **HTML no-JS POST Form + Region/Cookie/Header + Challenge 识别** |
| Brave Web | 不支持 | **新增零 Key Provider** |
| 海外 Image Search | 无独立路由 | **Bing Global → Openverse → Wikimedia** |
| Wikimedia Commons | 不支持 | **新增公开读 API Provider** |
| Provider 配置 | `provider-order` | **新增 `cn-provider-order` / `global-provider-order`，旧字段继续兼容** |
| 路由扩展 | Service 内逻辑 | **`SearchRouteResolver + ProviderChainResolver` 集中路由与链配置，为 JP/EU/自定义 Route 留扩展点** |

## 3. 核心设计原则

### 3.1 Route 与 Locale 分离

`region` 同时携带两种信息，但代码不能把两种职责混为一层：

```text
region = US
│
├─ 路由语义：GLOBAL
│
└─ Provider Locale：US / en-US
```

因此新增：

```text
io.github.changlu.openreach.routing.SearchRoute
io.github.changlu.openreach.routing.SearchRouteResolver
io.github.changlu.openreach.routing.ProviderChainResolver
io.github.changlu.openreach.routing.RegionLocaleSupport
```

职责分别是：

```text
SearchRoute             -> 当前只定义 CN / GLOBAL
SearchRouteResolver     -> region -> Route
ProviderChainResolver   -> Route -> Web/Image Provider Chain
RegionLocaleSupport     -> Route + region -> country / locale / Accept-Language / DDG region
```

Provider 不再自己发明“什么叫海外”。需要 Route/Locale 感知时统一复用 routing 层；Service 也不直接判断 CN/GLOBAL 配置字段，而是消费 `ProviderChainResolver` 返回的链。

### 3.2 不根据 Query 语言判断 Route

以下请求仍走 GLOBAL：

```json
{"query":"OpenAI 最新进展","region":"US"}
```

以下请求仍走 CN：

```json
{"query":"Spring Boot AI Agent","region":"CN"}
```

**显式地域优先于 Query 文本语言。**

### 3.3 显式 Provider 优先级最高

```json
{"query":"OpenAI","region":"CN","provider":"brave"}
```

不会先进入 CN auto chain，而是直接调用 Brave。`region` 仍会作为 Brave 的 Locale Hint 使用。

## 4. Route 规则

当前 `SearchRouteResolver`：

```text
region = null / "" / auto
    -> openreach.web.routing.default-route
    -> 默认 CN

region = CN / zh-CN / zh_CN / cn-zh / zh-Hans-CN / china
    -> CN

其他显式 region
    -> GLOBAL
```

因此：

```text
US / en-US / GB / SG / JP / DE / GLOBAL / wt-wt
-> GLOBAL
```

当前只暴露两类内部 Route，是为了保持 v1.0.2 简洁；未来新增：

```text
JP
EU
CUSTOM
```

时无需改变 API DTO，只扩 Resolver 与 Route Policy。

## 5. v1.0.2 Web Search 路由

### 5.1 CN

```text
bing (cn.bing.com)
  ↓
baidu
  ↓
sogou
  ↓
so360
  ↓
duckduckgo
```

保持 v1.0.1 主路径，避免国内能力回归。

### 5.2 GLOBAL

```text
brave
  ↓
duckduckgo
  ↓
bing (www.bing.com)
```

选择原因：

- 全部默认无需 API Key；
- Brave Web 有持续维护的公开 Web Interface 适配参考；
- DDG 有 HTML/Lite no-JS 路径；
- Bing Global 复用现有成熟 Parser，只切 Host / Locale；
- 三路索引来源并不完全相同，可降低单渠道依赖。

### 5.3 Brave Search Provider

新增：

```text
BraveSearchProvider
```

请求：

```text
https://search.brave.com/search?q=...&source=web
```

并设置：

```text
Accept-Language
safesearch Cookie
useLocation=0
summarizer=0
country
ui_lang
```

Parser 只解析真实结果块，不处理广告或 Brave 内部相对链接。

### 5.4 DuckDuckGo 强化

v1.0.2 不再用简单 GET Query 模拟 DDG HTML，而改为更符合当前 no-JS 页面流程的：

```text
POST https://html.duckduckgo.com/html/
Content-Type: application/x-www-form-urlencoded

q=...
b=
kl=...
```

同时增加：

```text
Referer
Sec-Fetch-Mode
Accept-Language
kl Cookie
```

并显式识别 bot challenge；发现 challenge 后立即抛 Provider 失败，让 Auto Chain 进入下一路，不建设 CAPTCHA 绕过。

### 5.5 Bing 全球化

同一个 `BingSearchProvider` 根据 Route 选择：

```text
CN     -> https://cn.bing.com/search
GLOBAL -> https://www.bing.com/search
```

不复制 `BingGlobalSearchProvider`，减少 Parser 重复维护。

## 6. v1.0.2 Image Search 路由

### 6.1 CN

```text
bing-cn -> baidu -> sogou -> openverse
```

保持原能力。

### 6.2 GLOBAL

正式落地：

```text
bing-global -> openverse -> wikimedia
```

### 6.3 为什么没有把 Brave Images 放 P0

前期调研确认 Brave Standard Web Interface 能覆盖 Images，但当前图片结果主要藏在页面内嵌 Svelte/JS 状态中，结构比 Brave Web DOM 更脆弱。

v1.0.2 的工程目标是：

> **少而稳，不为了 Provider 数量把高维护成本 Parser 放进默认链。**

因此 Brave Images 从原设计 P0 调整为观察项；等形成稳定 Fixture 与长期 Smoke 数据后再决定是否接入。

### 6.4 Wikimedia Commons

新增：

```text
WikimediaImageSearchProvider
```

使用公开 MediaWiki Action API：

```text
generator=search
gsrnamespace=6
prop=imageinfo
iiprop=url|size|mime|extmetadata
```

统一映射：

```text
imageinfo.url             -> imageUrl
imageinfo.thumburl        -> thumbnailUrl
imageinfo.descriptionurl  -> sourcePageUrl
width / height / mime     -> 图片信息
LicenseShortName          -> license
LicenseUrl                -> licenseUrl
```

并使用单独的可识别 User-Agent：

```yaml
wikimedia-user-agent: OpenReach/1.0.2 (+https://github.com/changluya/openreach)
```

## 7. 配置模型

```yaml
openreach:
  web:
    routing:
      default-route: cn

    search:
      provider: auto

      # v1.0.1 兼容字段
      provider-order:
        - bing
        - baidu
        - sogou
        - so360
        - duckduckgo

      # 默认留空并继承 provider-order，保证 v1.0.1 外部配置兼容。
      cn-provider-order: []

      global-provider-order:
        - brave
        - duckduckgo
        - bing

      bing-url: https://cn.bing.com/search
      bing-global-url: https://www.bing.com/search
      brave-url: https://search.brave.com/search
      duckduckgo-url: https://html.duckduckgo.com/html/

    image-search:
      provider: auto

      provider-order:
        - bing
        - baidu
        - sogou
        - openverse

      # 默认留空并继承 provider-order。
      cn-provider-order: []

      global-provider-order:
        - bing
        - openverse
        - wikimedia

      bing-url: https://cn.bing.com/images/async
      bing-global-url: https://www.bing.com/images/async
      openverse-url: https://api.openverse.org/v1/images/
      wikimedia-url: https://commons.wikimedia.org/w/api.php
```

### 7.1 兼容策略

如果旧部署只有：

```yaml
provider-order:
  - ...
```

且 `cn-provider-order` 未配置或为空，CN Route 自动继续使用旧 `provider-order`。项目内置 `application.yml` 也刻意把 `cn-provider-order` 保持为空，避免外部 v1.0.1 配置被新默认值遮蔽。

因此旧的国内部署配置不会因为升级 v1.0.2 立即失效。

## 8. 核心代码结构

```text
search/
  SearchService
  SearchProvider
  provider/
    BingSearchProvider
    BaiduSearchProvider
    SogouSearchProvider
    So360SearchProvider
    DuckDuckGoSearchProvider
    BraveSearchProvider            # v1.0.2

imagesearch/
  ImageSearchService
  ImageSearchProvider
  provider/
    BingImageSearchProvider
    BaiduImageSearchProvider
    SogouImageSearchProvider
    OpenverseImageSearchProvider
    WikimediaImageSearchProvider   # v1.0.2

routing/
  SearchRoute                      # v1.0.2
  SearchRouteResolver              # v1.0.2
  ProviderChainResolver            # v1.0.2
  RegionLocaleSupport              # v1.0.2
```

Service 只负责：

```text
请求参数
 -> resolve route
 -> ProviderChainResolver 获取能力链
 -> fallback / merge / deduplicate / limit / renumber
```

Provider 只负责：

```text
构造上游请求
 -> 解析结果
 -> 映射统一 DTO
```

## 10. 单元测试策略

v1.0.2 新增测试重点：

```text
SearchRouteResolver
  - auto 默认 CN
  - default-route=global
  - CN aliases
  - 所有显式非 CN -> GLOBAL
  - 非法默认值 fail-safe CN

ProviderChainResolver
  - CN legacy provider-order fallback
  - 显式 cn-provider-order override
  - GLOBAL Web/Image Chain 独立解析

RegionLocaleSupport
  - CN locale
  - US / JP locale
  - GLOBAL / wt-wt

SearchService
  - CN 只走 CN Chain
  - US 只走 GLOBAL Chain
  - auto 保持 v1.0.1 CN 行为
  - legacy provider-order 兼容
  - 原 fallback / dedupe / explicit provider 回归

ImageSearchService
  - GLOBAL Image Chain
  - auto CN 兼容
  - legacy provider-order 兼容
  - 原 fallback / dedupe 回归

BraveSearchProvider
  - 当前 snippet DOM Fixture

DuckDuckGoSearchProvider
  - 原结果解析

WikimediaImageSearchProvider
  - imageinfo
  - thumbnail/source page
  - width/height/mime
  - license/licenseUrl
  - 缺失字段容错
```

公网请求不进入 JUnit，避免网络波动导致 CI Random Fail；真实 Provider 可用性由 Smoke Test 验证。

## 14. v1.0.2 持续优化：Search 时间范围

本轮继续保持版本号 **v1.0.2**，在既有 CN / GLOBAL Route 上补充统一 `timeRange`：

```json
{
  "query": "latest Java AI Agent frameworks",
  "region": "US",
  "provider": "auto",
  "timeRange": "month"
}
```

标准值：`any / day / week / month / year`。兼容常见 `d/w/m/y`、`pd/pw/pm/py`、`qdr:*` 写法，但 Service 内部统一转换为 `SearchTimeRange` 枚举。

扩展设计：

```text
SearchRequest
  -> SearchTimeRange.parse
  -> SearchService
  -> SearchProvider.supportsTimeRange()
     ├─ false + auto      -> skip
     ├─ false + explicit  -> BAD_REQUEST
     └─ true              -> provider-specific mapping
```

`SearchProvider` 原三参数方法继续作为抽象方法保留，因此 v1.0.1 第三方 Provider 仍可直接加载；时间范围通过 default capability 方法增量扩展，不破坏旧 SPI。

当前实现：Brave、DuckDuckGo 支持真实上游时间过滤。没有可靠时间参数的 Provider 不伪造支持。

## 15. v1.0.2 持续优化：Image 可下载质量门禁

Image Search 从“发现 URL”升级为“返回当前真正可取得的图片 URL”。

```text
Image Provider
  -> 候选 over-fetch
  -> SecureImageDownloadVerifier
     -> UrlSafetyGuard
     -> Redirect re-check
     -> GET/Range prefix
     -> HTTP 2xx
     -> Content-Type reject HTML/XML/SVG
     -> Passive image magic bytes
  -> Downloadable Result
  -> dedupe / rank / limit
```

设计上把验证器抽为 `ImageDownloadVerifier` SPI，Service 不绑定具体网络探测实现；后续可扩缓存、CDN Probe、质量评分或异步健康状态，而不改变 Image Provider SPI。

`provider=auto` 时，如果某一路“搜得到但下载不了”，将继续下一 Provider；显式 Provider 则 fail-fast，避免给 Agent 返回无用 URL。

## 16. v1.0.2 持续优化：安全攻击面收敛

公网业务能力明确只有：

```text
POST /api/web/search
POST /api/web/image-search
POST /api/web/read
```

官网与文档只作为只读 classpath 静态资源。新增 `AttackSurfaceFilter` 做默认拒绝：

- 三个 API 精确 Path allowlist；
- 仅允许 POST + JSON；
- 禁止 Multipart / 文件上传；
- 禁止未知 API / Actuator / Debug / Upload / `/error` 直接访问；
- 禁止 PUT/PATCH/DELETE/TRACE 等非预期 Method；
- API Body 默认限制 64 KiB，同时覆盖 chunked 实际读取；
- Path Traversal / encoded path / backslash 等异常路径提前拒绝；
- 静态资源仅 `classpath:/static/`；
- 官网移除 inline script，配合严格 CSP；
- Read/Image remote fetch 统一限制公网 HTTP/HTTPS 80/443，每跳重定向复检 SSRF。

详细安全设计见：[v1.0.2安全加固设计.md](v1.0.2安全加固设计.md)。

## 17. 本轮兼容性结论

| 项目 | v1.0.1 / 既有 v1.0.2 调用 | 本轮行为 |
|---|---|---|
| Search 不传 `timeRange` | 无需修改 | 等价 `any` |
| 第三方 SearchProvider | 原三参数 SPI | 无需修改，默认 `supportsTimeRange=false` |
| Image Search 请求协议 | 无新增必填字段 | 无需修改，但输出质量变强 |
| Skill / Plugin | 原能力继续可用 | 增加时间参数并声明图片下载保证 |
| Health API | 旧文档曾提供 | 为收敛公网攻击面已移除；Skill doctor 改为只读 `GET /` |
| 三个核心 API | 保持路径和方法 | 完全兼容 |


## 18. 上游响应体资源边界

v1.0.2 安全复核新增统一资源边界：Web Search Provider HTML/JSON 默认最大 2 MiB，Image Search Provider 页面/JSON 默认最大 4 MiB。HTTP Client 使用 InputStream + bounded reader，不再把未知大小响应直接 `ofByteArray()` 全量读入 JVM。Read 继续使用既有 `max-bytes`，图片可下载探测只读取文件头，并使用固定并发、有界队列与 CallerRuns 背压，避免验证任务无界堆积。

该变化不影响外部 API，只提升异常上游、恶意跳转与资源耗尽场景下的稳定性。
