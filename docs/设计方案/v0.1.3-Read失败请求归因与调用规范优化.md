# v0.1.3 Read 失败请求归因与调用规范优化

> 分析基线：2026-08-18 导出的 15 条失败请求。目标不是“把所有失败都伪装成成功”，而是区分接口缺陷、目标站限制与调用方误用，并分别治理。

## 1. 结论总览

15 条失败可分为三组：

| 类型 | 数量 | 典型状态 | 责任判断 | 本次处理 |
|---|---:|---|---|---|
| 调用方误把内部附件/文件 URL 交给 Read | 10 | 400 | 调用方 | Skill 本地 fail-fast + 插件描述加强；服务端 SSRF 不放开 |
| 公网站点访问策略 / 前置条件 | 3 | 403 / 412 | 目标站为主，接口可增强错误语义 | 浏览器兼容 Header；结构化 `failureType/upstreamStatus/retryable`；403/412 不重试 |
| 公网站点瞬时源站/CDN 故障 | 2 | 521 | 上游为主，接口可提升韧性 | 521 纳入幂等 GET 有界重试 |

核心判断：**10/15 并不是 OpenReach 接口坏了，而是调用方把 OpenReach 当成了内网 HTTP/附件代理。** 这类请求如果直接放开 172.16/12 与 8999 端口，会破坏 SSRF 安全基线，因此必须在调用侧修正，而不是服务端放宽。

## 2. 失败逐类分析

### 2.1 内部附件 URL：调用方问题

典型入参：

```text
http://172.16.114.23:8999/images/chat/...png
http://172.16.114.23:8999/images/chat/...log
```

OpenReach `read` 的设计边界是：

```text
公网 HTTP/HTTPS
+ 80/443
+ HTML/XHTML/plain text
```

因此：

- `172.16.0.0/12` 属于私网；
- `8999` 属于非标准公网 Web 端口；
- `.png` 还是二进制图片，不属于 Read 正文提取对象；
- 即使 `.log` 可能是 text/plain，也不能因为内容是文本就允许访问内部地址。

本次治理：Skill 在真正请求 OpenReach 前先识别明显的私网 IP、非 80/443、图片/压缩包 URL 并直接报 `READ_TARGET_PRIVATE / READ_TARGET_PORT / READ_TARGET_BINARY`，Agent 应改用自身文件/图片读取能力。

### 2.2 国家卫健委 HTTP 412：目标站访问前置条件

两条 `nhc.gov.cn` Read 均返回 `412 Precondition Failed`。独立 Web 获取链路访问同样 URL 也能复现 412，因此不能归因成 OpenReach 连接超时或单机故障。

处理原则：

- 增加普通浏览器导航兼容 Header；
- 不携带 Cookie/Authorization，不模拟登录态；
- 412 视为 **non-retryable**，同一 URL 不机械重试；
- 返回结构化字段，调用方改选其他公开来源或退回 Search 证据。

### 2.3 HTTP 403：目标站明确拒绝

403 表示上游已经收到请求并拒绝当前访问。它不同于 DNS、连接超时或 5xx，不应自动重试，更不应通过关闭 TLS、伪造登录 Cookie 或破解挑战页“修复”。

调用方策略：换来源，而不是重试同一 URL。

### 2.4 CSDN HTTP 521：瞬时源站/CDN 故障

521 属于典型上游源站/CDN 不可用语义。Read 是幂等 GET，因此允许在服务端做一次有界重试是合理的；但不能让 Agent 再套多层无界重试。

本次将 `520~524` 与常见 `500/502/503/504` 纳入 Read 的有界 HTTP 状态重试，继续复用：

```yaml
max-attempts: 2
retry-backoff-ms: 200
```

## 3. 接口侧改造

### 3.1 Read 浏览器兼容 Header

增加：

```text
Cache-Control: no-cache
Pragma: no-cache
Upgrade-Insecure-Requests: 1
Sec-Fetch-Dest: document
Sec-Fetch-Mode: navigate
Sec-Fetch-Site: none
Sec-Fetch-User: ?1
```

仍不发送 Cookie、Authorization，也不绕过访问控制。

### 3.2 精细 HTTP 重试

重试：

```text
408 / 425 / 500 / 502 / 503 / 504 / 520~524
```

不重试：

```text
401 / 403 / 412 / 429
```

### 3.3 结构化错误元数据

保持历史兼容：

```json
"code": "UPSTREAM_ERROR"
```

同时增加：

```json
{
  "failureType": "HTTP_412",
  "upstreamStatus": 412,
  "retryable": false
}
```

这样 Agent 不需要解析 message 文本猜测是否应该重试。

## 4. Skill / AgentHub 插件侧改造

### 4.1 Skill 本地 fail-fast

`read(url)` 调用前本地识别：

```text
私网/localhost/.internal
非 80/443
明显图片/压缩包二进制 URL
```

识别成功后不再发起 OpenReach HTTP 请求，因此这类错误不会继续污染后端失败监控。

### 4.2 Agent 执行规则

```text
公开正文页           -> Read
内部附件/图片/日志    -> 调用方自己的文件/图片能力
403/412              -> 换来源，不重试同一 URL
521/瞬时 5xx          -> 交给 OpenReach 有界重试；仍失败则换来源
All connection attempts failed 且无 traceId
                     -> 排查 BASE_URL/Tool Runner 网络
```

## 5. 测试与验收点

新增/加强测试：

- Skill：私网附件 URL 在网络前拒绝；
- Skill：公网非 80/443 在网络前拒绝；
- Skill：公开图片二进制 URL 在网络前拒绝；
- Read：521 第一次失败、第二次成功；
- Read：412 不重试且 `retryable=false`；
- Read：浏览器导航 Header 存在，同时 Cookie/Authorization 不存在；
- Error Handler：`UPSTREAM_ERROR` 兼容不变，同时暴露 `failureType/upstreamStatus/retryable`；
- Classifier：结构化 412/521 精确分类；
- AgentHub 插件：版本、私网边界、412 降级规则写入配置。

安全验收：原有 `UrlSafetyGuard` 的私网、localhost、metadata、非 80/443、重定向 SSRF 规则全部保留，不为了提高成功率放宽。
