# 海外免费渠道深度调研与 OpenReach v1.0.2 接入结论

> 调研日期：**2026-08-15**  
> 目标版本：**OpenReach v1.0.2**  
> 调研口径：**只保留无需 API Key、无需注册账号、零调用费即可启动的渠道。** 需要 Key 的“免费额度 API”不进入本次设计。

---

## 1. 调研结论

OpenReach 不应该为了“Provider 数量多”接一堆脆弱渠道。v1.0.2 的目标是形成一条**少而稳、零 Key、可自动降级**的海外链路。

### 1.1 Web Search 最终结论

正式进入 v1.0.2：

```text
Brave Web
   ↓
DuckDuckGo HTML
   ↓
Bing Global Web
```

| 渠道 | API Key | 调用费 | 海外覆盖 | 接入方式 | v1.0.2 |
|---|---:|---:|---|---|---|
| **Brave Web Interface** | ❌ | 免费 | 高 | 公开 Web SERP | **P0 已落地** |
| **DuckDuckGo HTML no-JS** | ❌ | 免费 | 高 | HTML POST Form | **P0 已强化** |
| **Bing Global Web** | ❌ | 免费 | 高 | 公开 Web SERP | **P0 已落地全球路由** |

默认 GLOBAL Web Chain：

```text
brave -> duckduckgo -> bing
```

### 1.2 Image Search 最终结论

正式进入 v1.0.2：

```text
Bing Global Images
   ↓
Openverse
   ↓
Wikimedia Commons
```

| 渠道 | API Key | 接口稳定性 | 主要价值 | v1.0.2 |
|---|---:|---|---|---|
| **Bing Global Images** | ❌ | 中 | 通用图片覆盖 | **已落地全球路由** |
| **Openverse** | ❌ | 高 | 开放许可图片 | **沿用** |
| **Wikimedia Commons** | ❌ | 高 | 公共领域/开放许可/百科类图片 | **新增并落地** |

### 1.3 Read

v1.0.2 不改变默认 Read 主链：

```text
SafeHttpFetcher -> JsoupPageReader -> HtmlContentExtractor
```

仍坚持本地读取优先，不为了海外搜索扩展引入新的远端依赖。

---

## 2. “免费渠道”的硬门槛

一个渠道只有同时满足以下条件，才进入本轮候选：

1. 无需 API Key / Token；
2. 无需注册账号；
3. 默认零调用费；
4. 能直接通过 HTTP/HTML/Public Read API 使用；
5. 不依赖验证码绕过、代理池、账号池；
6. 能映射到 OpenReach 现有 SPI；
7. 有当前仍维护的公开实现/官方接口作为工程依据；
8. 维护成本与结果质量匹配。

因此 Tavily、Exa、Brave Search API、Serper 等即使存在免费额度，也**不属于本次 v1.0.2 的免费渠道定义**。

---

## 3. Brave Web：海外 Web 第一优先级

SearXNG 当前仍维护 Brave Standard Engine，并明确区分：

```text
brave     -> Web Interface，无 API Key
braveapi  -> 官方 API，需要 API Key
```

本项目只采用前者。

### 优点

- Brave 有独立 Web 索引，能降低对 Bing 的单一依赖；
- 英文及欧美信息覆盖较强；
- 当前 Web 结果仍可从 HTML `snippet` 结果块解析；
- 不增加运行时依赖，Java HTTP + Jsoup 即可实现；
- 与现有 `SearchProvider` SPI 完全匹配。

### 风险

- Web Interface 不是稳定 API 合同；
- DOM 可能改版；
- 深分页/高频请求可能触发限流；
- 部分非拉丁语言结果质量一般。

### v1.0.2 策略

```text
只做第一页 Top-N
不做 CAPTCHA 绕过
失败立即 fallback
Fixture 固化当前 DOM
```

参考：

- https://search.brave.com/
- https://docs.searxng.org/dev/engines/online/brave.html
- https://docs.searxng.org/_modules/searx/engines/brave.html

---

## 4. DuckDuckGo HTML：保留，但必须按当前 no-JS 流程强化

v1.0.1 已有 DuckDuckGo Provider，但旧实现是：

```text
GET /html/?q=...&kl=...
```

当前 SearXNG 文档显示 DDG HTML/Lite 的 no-JS 主流程使用 **POST Form**，并且 bot blocker 会参考：

```text
User-Agent
Accept-Language
Referer
Sec-Fetch-Mode
region cookie
```

因此 v1.0.2 已改成：

```text
POST https://html.duckduckgo.com/html/

q
b
kl
```

并增加 challenge 识别。

### 为什么仍然保留

- 全球覆盖较好；
- 不需要 Key；
- 与 Brave/Bing 形成不同来源补充；
- HTML/Lite 是公开 no-JS 使用路径。

### 已知边界

- 高频访问可能临时封 IP；
- 后续分页涉及 `vqd`，维护成本明显提升；
- 所以 v1.0.2 只保证首屏 Top-N。

参考：

- https://docs.searxng.org/dev/engines/online/duckduckgo.html

---

## 5. Bing Global：复用现有成熟能力，不复制 Provider

v1.0.1 已有：

```text
https://cn.bing.com/search
https://cn.bing.com/images/async
```

v1.0.2 新增：

```text
https://www.bing.com/search
https://www.bing.com/images/async
```

并由统一 Route 决定：

```text
CN     -> cn.bing.com
GLOBAL -> www.bing.com
```

这样可以继续复用同一套 Parser，而不是维护 `bing-cn` / `bing-global` 两份实现。

Bing 在 GLOBAL 链中放第 3 路，主要作用是：

```text
Brave/DDG 失败后的成熟兜底
```

---

## 6. Openverse：继续作为海外图片稳定补充

Openverse 官方 API 明确支持 anonymous 使用，符合本轮零 Key 定义。

优势：

- 正式公开 API；
- JSON Schema 比搜索页 DOM 稳定；
- 部分结果直接带 License / License URL；
- 对内容生产、合法配图非常有价值。

它不是通用图片搜索的完全替代，但非常适合作为：

```text
Bing Images 后的稳定开放许可补充源
```

参考：

- https://api.openverse.org/

---

## 7. Wikimedia Commons：本轮最值得新增的图片 Provider

Wikimedia Commons 使用公开 MediaWiki Action API，无需 API Key。

推荐调用链：

```text
generator=search
  ↓
namespace=File
  ↓
imageinfo
  ↓
url / thumburl / descriptionurl / size / mime / extmetadata
```

非常适合：

- 历史人物；
- 地理景点；
- 百科主题；
- 公共领域素材；
- Creative Commons 图片。

v1.0.2 已新增 `WikimediaImageSearchProvider`，并映射：

```text
LicenseShortName -> license
LicenseUrl       -> licenseUrl
```

Wikimedia 对自动化客户端建议使用可识别 User-Agent，因此工程单独增加：

```yaml
wikimedia-user-agent: OpenReach/1.0.2 (+https://github.com/changluya/openreach)
```

参考：

- https://www.mediawiki.org/wiki/Wikimedia_APIs
- https://www.mediawiki.org/wiki/API:Imageinfo

## 8. 为什么 Brave Images 没有进入 v1.0.2 默认链

前期调研曾把 Brave Images 列为 P0，因为 SearXNG 的 Brave Standard Engine 确实支持 Images。

但进一步拆解当前实现后发现，Brave Images 不是像 Web Search 一样直接解析稳定 DOM，而是需要从页面内嵌 Svelte/JS 状态提取数据，再转换 JavaScript Object 结构。

这意味着：

```text
页面构建产物变化
 -> 内嵌状态位置变化
 -> JS Object 语法变化
 -> Parser 整体失效
```

对于 OpenReach v1.0.2：

```text
Bing Global + Openverse + Wikimedia
```

已经能够形成三路互补链路，因此没有必要为了多一个 Provider 引入高脆弱 Parser。

结论：

```text
Brave Web    -> P0
Brave Images -> P2 / 观察项
```

## 9. 未进入默认链的其他海外渠道

### Startpage

无需 Key，但通常需要动态 Cookie/Token，并且 CAPTCHA 风险较高。当前不值得为它引入状态机。

### Qwant

存在可访问接口/页面实现，但未公开接口稳定性不足，暂不进入核心链。

### Yahoo

搜索质量可以，但公开页面协议与近期适配稳定性不够理想；没有必要在已有 3 路 Web Chain 的情况下继续扩大维护面。

### Mojeek

独立索引有价值，但公开页面作为自动化 Provider 的稳定性与结果量不够适合默认链，保留观察。

### Mwmbl / Marginalia

非常有开源/独立搜索价值，但索引规模与通用搜索覆盖不足，更适合作为实验 Provider，而不是 Agent 默认 Web Search。

## 11. 海外调研最终结论

本轮最重要的结论不是“海外免费渠道有多少”，而是：

> **真正适合 OpenReach 默认接入的高质量零 Key 渠道并不多。应该优先把少数成熟渠道做深，把 Route、Fallback、Parser Test、Locale 与失败边界做扎实。**

最终 v1.0.2 选择：

```text
Web:
  Brave Web
  DuckDuckGo HTML
  Bing Global

Image:
  Bing Global Images
  Openverse
  Wikimedia Commons
```

这 6 个能力点中，Bing / DDG / Openverse 是在 v1.0.1 基础上的强化复用，真正新增 Provider 只有：

```text
BraveSearchProvider
WikimediaImageSearchProvider
```

因此 v1.0.2 没有把系统变成难以维护的“渠道大杂烩”，而是完成了更关键的架构升级：

```text
单一国内优先 Provider Chain
        ↓
region-aware CN / GLOBAL Web Access Router
```

同时继续坚持：

```text
零 API Key
零商业 Search 依赖
不绕 CAPTCHA
Provider best-effort
Auto Route 保底
```

这就是当前海外免费渠道调研后的最终落地结论。
