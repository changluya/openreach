## 1. 验收硬规则

正式 Java Gate：

```bash
mvn clean test
```

必须满足：

```text
Failures = 0
Errors   = 0
BUILD SUCCESS
```

公网免费 Provider 会受到 DNS、出口 IP、403/429、CAPTCHA、页面改版影响，因此：

```text
离线 JUnit Fixture / Service Test = 代码正确性 Gate
公网 Smoke Test                  = 运行环境与上游可用性 Gate
```

二者必须分离，不能把公网随机性写进稳定单测。

## 3. v1.0.2 Route 必测矩阵

`SearchRouteResolver` 是本版本的核心新增层，必须覆盖：

| 输入 | 期望 Route | 说明 |
|---|---|---|
| `null` / blank | 默认 Route | 默认配置为 CN |
| `auto` | 默认 Route | 保持 v1.0.1 国内优先 |
| `CN` | CN | 标准国家码 |
| `zh-CN` / `zh_CN` | CN | Locale alias |
| `cn-zh` / `zh-Hans-CN` / `china` | CN | 兼容 alias |
| `US` / `GB` / `SG` / `JP` | GLOBAL | 显式非 CN 地区 |
| `GLOBAL` / `wt-wt` | GLOBAL | 世界范围 |
| `default-route=global` + `auto` | GLOBAL | 可配置默认 Route |
| 非法 `default-route` | CN | fail-safe，不意外把旧部署切海外 |

同时必须验证：**Query 是中文还是英文不能改变 Route**，Route 只由 `region` / default-route 决定。

## 4. Provider Chain Resolver 测试

`ProviderChainResolverTest` 验证 Route 与能力链配置集中解析：

```text
Search / CN     -> cn-provider-order；为空时继承 legacy provider-order
Search / GLOBAL -> global-provider-order
Image / CN      -> cn-provider-order；为空时继承 legacy provider-order
Image / GLOBAL  -> global-provider-order
Web 与 Image 的链配置互不串线
```

这样未来新增 JP / EU 等 Route 时，Service 无需新增地区分支。

---

## 5. Region 与 Provider Locale 分层测试

`RegionLocaleSupportTest` 验证：

```text
CN -> CN / zh-CN / cn-zh
US -> US / en-US / en-us
JP -> JP / ja-JP / ja-jp
GLOBAL / wt-wt -> GLOBAL Route + worldwide DDG region
```

目标不是实现商业级 Geo，而是保证：

```text
Route Selection
      !=
Provider Locale Hint
```

Provider 不允许重新实现一套 CN/GLOBAL 判断。

## 6. Web Search Service 测试

`SearchServiceTest` 至少覆盖：

1. v1.0.1 fallback：A 失败后 B 成功；
2. 多 Provider URL 去重；
3. 统一 rank；
4. 显式 Provider 不 fallback；
5. 全部 Provider 失败返回 `UpstreamException`；
6. `region=CN/zh-CN` 只使用 CN Chain；
7. `region=US` 使用 GLOBAL Chain；
8. `region=auto` 默认仍走 CN；
9. 旧 `provider-order` 在未配置 `cn-provider-order` 时继续生效；
10. GLOBAL Provider Order 为空时给出明确配置错误；
11. Provider Order 中 blank / null / 大小写 / 前后空格可容错；
12. Provider 返回 null/empty 时视为单路失败而不是打断整个链；
13. 显式 Provider 优先级高于 Route：`region=US + provider=baidu` 仍只执行 Baidu。

### 默认链

```text
CN:
  bing -> baidu -> sogou -> so360 -> duckduckgo

GLOBAL:
  brave -> duckduckgo -> bing
```

## 10. Read / SSRF 回归

v1.0.2 没有改变 Read 主架构，但以下测试必须继续作为升级回归门禁：

```text
HtmlContentExtractor
UrlSafetyGuard
```

核心安全边界：

```text
拒绝非 HTTP/HTTPS
拒绝 localhost / loopback
拒绝私网地址
拒绝危险 DNS 解析结果
Redirect 后重新检查
限制 Redirect 次数
限制响应体大小
```

海外 Search 改造不能降低 Read 安全级别。

## 13. 公网 Smoke Test

公网 Smoke 不替代 JUnit。推荐顺序：

```text
1. Skill check（配置已存在时仅 1 次无副作用 API Probe）
2. CN Web auto
3. GLOBAL Web auto
4. Brave explicit
5. DuckDuckGo explicit
6. Bing Global explicit
7. CN Image auto
8. GLOBAL Image auto
9. Openverse explicit
10. Wikimedia explicit
11. Read
```

工程脚本：

```bash
./bin/quick/smoke-test.sh
```

如果单一公开 Provider 出现 403 / 429 / challenge，但 Auto Chain 能 fallback 获得结果，应记录为 Provider 健康问题；如果整条 Route 无结果，则该运行环境公网验收失败。


## 15. Release Gate

标准发版环境执行：

```bash
# Java JUnit + Skill Python Test
./bin/quick/check-project.sh

# clean package 同样会执行 Java Test，并追加 Skill Python Test
./bin/quick/package.sh
```

或最小 Gate：

```bash
mvn clean test
```

最终验收清单：

```text
[ ] Java 100 个 @Test 全部通过
[ ] Skill 12 个 Python Test 全部通过
[ ] Failures = 0 / Errors = 0
[ ] CN Route 回归通过
[ ] GLOBAL Route 通过
[ ] 显式 Provider 行为通过
[ ] Parser Fixture 通过
[ ] Search timeRange alias / provider capability / upstream mapping 通过
[ ] Image 可下载过滤 / fallback / signature 通过
[ ] AttackSurface：仅三 API、禁上传、禁危险 Method、Path/Body Limit 通过
[ ] SSRF 回归通过
[ ] application.yml 可解析
[ ] AgentHub Plugin JSON 可解析
[ ] README / docs 内链有效
[ ] ZIP 完整性通过
[ ] 目标部署环境 Smoke Test 通过
```

> 当前交付容器没有预装 Maven；尝试通过系统包管理与 Apache 官方发行包补齐时受到容器 DNS/下载策略限制。因此本轮可执行 Skill Python 12/12、JDK17 核心源码隔离编译、图片 HTTP Probe Harness、脚本/配置/文档/ZIP 校验，但不把这些替代成虚假的 `mvn clean test BUILD SUCCESS`。标准 Maven 环境仍必须运行 `./bin/quick/check-project.sh` 作为最终 Java Release Gate。
