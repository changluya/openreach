# 核心测试与验收


> 相关接口流程：[`WebSearch`](核心搜索接口设计/01-websearch核心流程设计.md) · [`ImageSearch`](核心搜索接口设计/02-imagesearch核心流程设计.md) · [`Read`](核心搜索接口设计/03-read核心流程设计.md)

## 1. 验收硬规则

本工程保持用户要求：

> **全部单元测试通过后，才允许正式标记为验收通过。**

正式本地 Gate：

```bash
mvn clean test
```

必须看到：

```text
Failures = 0
Errors   = 0
BUILD SUCCESS
```

公网 Search/Image Search 会受到网络、限流、页面改版影响，所以公网请求属于 Smoke Test，不作为离线 JUnit 的不稳定依赖。

# 3. 为什么 Provider Parser 单测必须使用 Fixture

不能把 CI 单测写成：

```text
JUnit -> 实时请求百度/Bing
```

否则：

```text
代码没变化
↓
公网 429 / CAPTCHA / DNS
↓
Build Random Fail
```

所以 Parser 测试使用固定 HTML/JSON Fixture，验证：

```text
上游代表性结构
   ↓
Provider Parser
   ↓
统一 DTO
```

公网真实页面变化由：

```text
Smoke Test
线上 Metrics
Bad Case Fixture
```

闭环回归。

# 14. 验收状态定义

建议使用三个状态：

```text
开发完成
  -> 代码/Fixture/文档已准备

单测通过
  -> mvn clean test 全绿

正式验收
  -> 单测全绿 + 本机 Smoke 达到最低标准
```

由于免费搜索上游属于 best-effort：

> 单个 Provider 在某一网络环境下临时不可用，不等价于 Auto 能力整体失败；但如果 Auto 在目标部署网络长期无法获得有效结果，则不能通过 Search Smoke 验收。

# 15. Sogou ImageSearch 启动回归测试

本版本修复过一次启动级故障：旧实现通过静态正则直接截取 `window.__INITIAL_STATE__`，正则中的 `{` 导致 `PatternSyntaxException`，使 `SogouImageSearchProvider` 在类初始化阶段抛出 `ExceptionInInitializerError`，进而导致整个 Spring ApplicationContext 启动失败。

修复后不再依赖该正则，而是：

```text
定位 window.__INITIAL_STATE__
  ↓
寻找赋值后的首个 {
  ↓
按对象括号深度扫描
  ↓
识别引号与转义字符
  ↓
提取完整嵌套 JSON
  ↓
JsonMapper 解析
```

新增回归点：

- 多层嵌套对象可完整提取；
- 字符串内部出现 `}`、`;` 不会提前截断；
- 缺少 State 或 JSON 不完整时安全返回空结果；
- Provider 类加载阶段不再编译脆弱正则。
