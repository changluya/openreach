# OpenReach 当前工程能力与渠道支持

> 当前版本：**v1.0.2**
> 核心定位：面向 AI Agent 的开源 Web 访问基础设施，默认优先使用**无需 API Key 的免费渠道**。

---

## 1. 当前三大原语

```text
search(query)        -> 网页搜索 / 发现信息源
image-search(query)  -> 文搜图 / 发现图片
read(url)            -> 网页读取 / 提取正文
```

HTTP 接口：

```text
POST /api/web/search
POST /api/web/image-search
POST /api/web/read
```

---

## 2. v1.0.2 核心升级：CN / GLOBAL 双路由

v1.0.1 中 `region` 主要作为 Provider Hint，自动路由只有一条全局 `provider-order`。

v1.0.2 增加：

```text
SearchRoute
SearchRouteResolver
ProviderChainResolver
RegionLocaleSupport
```

核心流程：

```text
provider != auto
    -> 直接指定 Provider

provider = auto
    -> region
    -> SearchRouteResolver
       ├─ CN
       └─ GLOBAL
    -> ProviderChainResolver
    -> 对应 Provider Chain
```

路由规则：

```text
CN / zh-CN / zh_CN / cn-zh / zh-Hans-CN / china -> CN
US / GB / SG / JP / DE / GLOBAL / wt-wt / 其他非 CN -> GLOBAL
null / blank / auto -> default-route，默认 CN
```

`region=auto` 默认继续走 CN，因此对 v1.0.1 国内调用行为保持兼容。

## 3. Web Search 当前支持

### 3.1 CN Route

```text
bing -> baidu -> sogou -> so360 -> duckduckgo
```

| Provider | 标识 | API Key | 说明 |
|---|---|---:|---|
| Bing 中国 | `bing` | ❌ | `cn.bing.com` 公开搜索页 |
| 百度 | `baidu` | ❌ | 中文核心 fallback |
| 搜狗 | `sogou` | ❌ | 国内补充 |
| 360 搜索 | `so360` | ❌ | 国内补充 |
| DuckDuckGo | `duckduckgo` | ❌ | HTML no-JS 兜底 |

### 3.2 GLOBAL Route

```text
brave -> duckduckgo -> bing
```

| Provider | 标识 | API Key | 说明 |
|---|---|---:|---|
| Brave Web | `brave` | ❌ | v1.0.2 新增公开 Web Interface Provider |
| DuckDuckGo HTML | `duckduckgo` | ❌ | v1.0.2 强化为 POST Form + Locale/Header/Challenge 识别 |
| Bing Global | `bing` | ❌ | 同一 Provider 根据 Route 使用 `www.bing.com` |

### 3.3 Search 时间范围

`POST /api/web/search` 新增可选字段 `timeRange`：

```text
any（默认） / day / week / month / year
```

同时兼容 `d/w/m/y`、`pd/pw/pm/py`、`qdr:d/qdr:w/qdr:m/qdr:y`。Service 会先规范化为 `SearchTimeRange`，Provider 只处理枚举，不感知外部 alias。指定非 `any` 后：

- `provider=auto`：自动跳过没有真实时间过滤能力的 Provider；
- 显式 Provider：若不支持时间过滤则直接 `BAD_REQUEST`，禁止静默忽略；
- 当前 Brave 映射 `pd/pw/pm/py`，DuckDuckGo 映射 `d/w/m/y`；
- 搜索响应增加规范化后的 `timeRange` 字段。

### 3.4 Search Auto 行为

- 单 Provider 超时/解析失败/空结果 -> 继续下一路；
- URL 规范化去重；
- 达到 `limit` 提前结束；
- 最终 Rank 统一重排；
- 所有 Provider 都失败 -> `UPSTREAM_ERROR`；
- 显式 Provider 失败时**不会静默 fallback**。

## 4. Image Search 当前支持

### 4.1 CN Route

```text
bing -> baidu -> sogou -> openverse
```

### 4.2 GLOBAL Route

```text
bing -> openverse -> wikimedia
```

| Provider | 标识 | API Key | 主要输出 |
|---|---|---:|---|
| Bing Images | `bing` | ❌ | 原图、缩略图、来源页、尺寸 |
| 百度图片 | `baidu` | ❌ | 中文图片、来源页、尺寸 |
| 搜狗图片 | `sogou` | ❌ | 国内补充图片源 |
| Openverse | `openverse` | ❌ | 开放许可图片、License |
| Wikimedia Commons | `wikimedia` | ❌ | v1.0.2 新增，公开 MediaWiki API + License Metadata |

统一 DTO：

```text
rank
title
imageUrl
thumbnailUrl
sourcePageUrl
provider
source
domain
width
height
imageFormat
license
licenseUrl
```

### 4.3 原图可下载强校验

Image Search 不再把 Provider 返回的 URL 直接透传。Service 会按 `limit × candidateMultiplier` 多取候选，并通过 `SecureImageDownloadVerifier` 并发探测：

```text
Provider Candidates
  -> UrlSafetyGuard（公网 HTTP/HTTPS + 80/443）
  -> 每次 Redirect 再校验
  -> 2xx HTTP
  -> 拒绝 text/html/xml/svg
  -> 小前缀真实字节签名识别
  -> JPEG/PNG/GIF/WebP/BMP/TIFF/ICO/AVIF/HEIC 等被动图片
  -> 返回最终 items
```

如果某个 Provider 有搜索结果但没有任何可下载图片，`auto` 会继续下一 Provider；显式 Provider 则返回 `UPSTREAM_ERROR`。因此响应中的 `imageUrl` 表示**响应生成时已验证可直接下载**，而不是仅仅“搜索页里出现过的图片地址”。

### 4.4 Brave Images 状态

**未放入 v1.0.2 默认链。**

原因：当前 Brave Images 公开页依赖内嵌 Svelte/JS 状态解析，维护脆弱度高于 Brave Web。现有 `Bing Global + Openverse + Wikimedia` 已形成三路互补，因此先保证稳定性，不为了数量强行接入。

## 5. Web Read 当前支持

主链：

```text
WebReadService
  -> PageReader SPI
  -> JsoupPageReader
  -> SafeHttpFetcher
  -> UrlSafetyGuard
  -> HtmlContentExtractor
```

支持：

- HTML/SSR 页面读取；
- Redirect；
- 最终 URL；
- Title；
- Description Metadata；
- 正文抽取；
- Links；
- `maxChars`；
- 响应体大小限制；
- Timeout；
- SSRF 防护。

当前仍不默认引入远端 Reader，保持本地、自托管、无第三方凭证依赖。

## 6. 安全基线 / 公网攻击面

OpenReach v1.0.2 采用默认拒绝：公网业务接口严格只有三个 JSON POST API：

```text
POST /api/web/search
POST /api/web/image-search
POST /api/web/read
```

另外只允许官网只读静态资源：`/`、`/docs/**`、`/assets/**`、`/community`、`/downloads/openreach-skill.zip`。不存在公开 Health、Upload、Actuator、Debug 或任意文件写入接口。

统一 `AttackSurfaceFilter`：

- 精确 API Path allowlist；
- API 仅 POST + `application/json`；
- 明确拒绝 `multipart/form-data`，Spring Multipart 同时全局关闭；
- 拒绝未知端点和危险 HTTP Method；
- 请求体默认最大 64 KiB，声明长度和真实读取都做上限；
- 拒绝 `..`、反斜线、分号、百分号编码等异常 Path；
- 官网脚本全部为同源静态 JS，配置 CSP / nosniff / DENY frame / Permissions-Policy 等 Header；
- 静态资源仅从 `classpath:/static/` 提供，不映射宿主文件系统。

Read 和 Image 下载探测共用 `UrlSafetyGuard`，拒绝：

```text
非 HTTP(S) / user-info / 非 80,443 端口
localhost / *.local / *.internal
loopback / RFC1918 / link-local / CGNAT / benchmark / TEST-NET / multicast / IPv6 ULA 等
DNS 解析到禁止地址
Redirect 到禁止地址
```

> 网络层仍建议在生产部署中配置容器只读文件系统、非 root、`cap_drop: ALL` 与出口 ACL/WAF。应用层 SSRF 校验不能替代基础设施层 egress 防护。

OpenReach 不建设验证码绕过、代理池、账号池、反爬对抗或登录态抓取。

## 7. v1.0.2 配置

```yaml
openreach:
  web:
    routing:
      default-route: cn

    search:
      provider: auto
      provider-order: [bing, baidu, sogou, so360, duckduckgo] # v1.0.1兼容
      cn-provider-order: [] # 默认继承 provider-order；显式配置时才覆盖 CN 链
      global-provider-order: [brave, duckduckgo, bing]
      max-response-bytes: 2097152 # 2 MiB 上游 HTML/JSON 硬上限
      bing-url: https://cn.bing.com/search
      bing-global-url: https://www.bing.com/search
      brave-url: https://search.brave.com/search
      duckduckgo-url: https://html.duckduckgo.com/html/

    image-search:
      provider: auto
      provider-order: [bing, baidu, sogou, openverse] # v1.0.1兼容
      cn-provider-order: [] # 默认继承 provider-order
      global-provider-order: [bing, openverse, wikimedia]
      max-response-bytes: 4194304 # 4 MiB 上游页面/JSON 硬上限
      bing-url: https://cn.bing.com/images/async
      bing-global-url: https://www.bing.com/images/async
      openverse-url: https://api.openverse.org/v1/images/
      wikimedia-url: https://commons.wikimedia.org/w/api.php
      download-candidate-multiplier: 3
      download-max-candidates: 60
      download-validation-timeout-ms: 4000
      download-validation-max-redirects: 3
      download-validation-max-bytes: 65536
      download-validation-concurrency: 6
      download-validation-queue-capacity: 48 # 有界队列 + CallerRuns 背压

    read:
      allowed-ports: [80, 443]

    security:
      max-api-body-bytes: 65536
```

## 9. 扩展接口

当前仍保持三套 SPI：

```java
public interface SearchProvider {
    String name();
    List<SearchItem> search(String query, int limit, String region); // v1.0.1兼容
    default boolean supportsTimeRange() { return false; }
    default List<SearchItem> search(String query, int limit, String region, SearchTimeRange timeRange) { ... }
}
```

```java
public interface ImageSearchProvider {
    String name();
    List<ImageSearchItem> search(String query, int limit, String region);
}
```

```java
public interface PageReader {
    String name();
    ReadResponse read(...);
}
```

Search SPI 仍保留原三参数抽象方法，因此 v1.0.1 第三方 Provider 不改代码仍可接入；时间过滤以 default capability 方法增量扩展。`SearchRouteResolver` 负责 region → Route，`ProviderChainResolver` 负责 Route → Web/Image Provider Chain，Service 只执行链路与聚合，后续扩 JP/EU 不需要把地区分支散进 Service。

## 11. 当前能力边界

免费公开搜索页仍属于 best-effort：

- DOM / 内嵌 JSON 可能变化；
- 可能出现 403/429；
- 可能出现 CAPTCHA / bot challenge；
- 不承诺商业 SLA；
- 地区网络出口会影响结果。

v1.0.2 的策略不是消除这些客观风险，而是通过：

```text
Route-aware Provider Chain
+ 多路 fallback
+ Parser Fixture Test
+ Challenge fail-fast
+ SPI 可扩展
```

把单一免费渠道失效对 Agent 上层的影响降到最低。
