# 当前工程能力与渠道支持

> 当前开源工程版本：**OpenReach v0.1.0**

> 当前版本：OpenReach v0.1.0  
> 核心定位：给 Agent 提供 **Web Search + Image Search + Web Read** 三个轻量、可组合、可替换 Provider 的 Web 基础原语。


> 相关接口流程：[`WebSearch`](核心搜索接口设计/01-websearch核心流程设计.md) · [`ImageSearch`](核心搜索接口设计/02-imagesearch核心流程设计.md) · [`Read`](核心搜索接口设计/03-read核心流程设计.md)

---

# 1. 当前能力总览

当前 Spring Boot 服务暴露三个接口：

```text
POST /api/web/search        普通网页搜索
POST /api/web/image-search  文搜图
POST /api/web/read          网页读取
```

整体关系：

```text
                          Agent
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
       search          image-search          read
          │                 │                 │
          ▼                 ▼                 ▼
   SearchProvider     ImageSearchProvider   PageReader
          │                 │                 │
   多免费搜索源        多免费图片源        Safe Fetch + Jsoup
```

当前仍保持：

- JDK 17 + Spring Boot；
- 单 Spring Boot 进程即可运行；
- 无 Docker / Python 强依赖；
- 无 Serper/Tavily 等商业 Search API Key；
- 第三方 Search API 调用费为 0；
- Provider SPI 已为商业渠道预留扩展位置。

# 2. 普通 Web Search 当前渠道

当前接入 **5 路免费 Web Search Provider**。

| Provider | `provider` | Auto 顺序 | 入口 | 国内定位 | 接入方式 | 主要作用 |
|---|---|---:|---|---|---|---|
| Bing 中国 | `bing` | 1 | `cn.bing.com` | 国内优先 | HTML SERP | **默认第一路** |
| 百度 | `baidu` | 2 | `baidu.com` | 国内主流 | HTML SERP | 中文核心 fallback |
| 搜狗 | `sogou` | 3 | `sogou.com` | 国内搜索 | HTML SERP | fallback |
| 360 搜索 | `so360` | 4 | `so.com` | 国内搜索 | HTML SERP | fallback |
| DuckDuckGo | `duckduckgo` | 5 | `html.duckduckgo.com` | 海外 | HTML SERP | 最后兜底 |

默认：

```yaml
provider: auto
provider-order:
  - bing
  - baidu
  - sogou
  - so360
  - duckduckgo
```

Auto 逻辑：

```text
Bing
 ↓ 失败 / 数量不足
Baidu
 ↓
Sogou
 ↓
360
 ↓
DuckDuckGo
 ↓
URL 去重 + 统一 rank
```

某个上游出现：

```text
Timeout
403 / 429
页面结构变化
解析为空
```

不会立即让 `auto` 整体失败，而是继续后续 Provider。

# 3. 普通 Search 能力边界

| 能力 | 状态 | 说明 |
|---|---:|---|
| 普通 Web Search | ✅ | 多搜索源 best-effort |
| Title | ✅ | 搜索结果标题 |
| URL | ✅ | 候选页面 URL |
| Snippet | ✅ 基础 | 上游页面有则返回 |
| Rank | ✅ | 聚合后统一编号 |
| Source | ✅ | 标记来自哪个 Provider |
| URL 去重 | ✅ | Service 层处理 |
| Limit | ✅ | 1~20 |
| Provider 显式选择 | ✅ | 便于渠道诊断 |
| Region | ⚠️ 基础 | 仅部分 Provider 真正支持 |
| Pagination | ❌ | 当前仅首屏 |
| Freshness | ❌ | 尚未形成跨 Provider 统一协议 |
| Knowledge Graph | ❌ | 免费统一 DTO 暂不承载 |
| Google Top10 一致性 | ❌ | 不是 Google 官方/商业 SERP |
| 精确 Geo | ❌ | 不承诺商业级位置定位 |
| SLA / 高 QPS | ❌ | 免费网页上游无 SLA |

### 关键边界

当前 5 路并不是相应搜索引擎的正式商业 API，而是对公开搜索结果页面做 best-effort 解析。

所以它们天然可能受：

```text
DOM 改版
A/B 页面结构
反自动化策略
CAPTCHA
429
网络出口
```

影响。

当前策略是：

> **多 Provider 容错，而不是通过账号池、住宅代理池、CAPTCHA 绕过系统去硬抗单一搜索引擎。**

# 4. 文搜图 Image Search 当前渠道

OpenReach v0.1.0 新增独立接口：

```text
POST /api/web/image-search
```

当前接入 **4 路 Image Search Provider**：

| Provider | `provider` | Auto 顺序 | 接入方式 | 是否正式 API | 国内定位 | 当前价值 |
|---|---|---:|---|---:|---|---|
| Bing Images | `bing` | 1 | `cn.bing.com/images/async` 结果解析 | ❌ | 国内优先 | **通用图片默认第一路** |
| 百度图片 | `baidu` | 2 | Baidu Images `acjson` + Cookie warmup | ❌ | **国内核心** | 中文图片 fallback |
| 搜狗图片 | `sogou` | 3 | 图片页 `window.__INITIAL_STATE__` 解析 | ❌ | 国内 | fallback |
| Openverse | `openverse` | 4 | `api.openverse.org/v1/images/` | ✅ | 海外/开放内容 | **带 License 元数据的补充源** |

默认：

```yaml
image-search:
  provider: auto
  provider-order:
    - bing
    - baidu
    - sogou
    - openverse
```

# 5. 为什么 OpenReach v0.1.0 选择这四路图片源？

## 5.1 Bing Images

选择原因：

- 中国入口 `cn.bing.com`；
- 图片结果中通常可以取得原图、缩略图、来源页和尺寸；
- 作为通用 Web 图片 Discovery 覆盖度较好；
- 不增加额外 SDK / sidecar。

当前解析模型参考成熟开源元搜索引擎对 Bing Images 的实现思路，但本工程直接以 Java 实现自己的 Provider SPI。

不足：

- 不是正式 Search API；
- HTML/内部异步结果结构可能调整；
- 无 SLA。

---

## 5.2 百度图片

选择原因：

- 国内中文图片搜索的重要来源；
- 当前图片结果能获得：原图 URL、缩略图、来源页、站点、宽高、格式等；
- SearXNG 当前官方源码也采用 `image.baidu.com/search/acjson` 路径，并先访问百度图片首页获取 Cookie。

当前 Java 实现同样采用：

```text
warmup image.baidu.com
      ↓
缓存 Set-Cookie
      ↓
/search/acjson
      ↓
parse data[]
```

不足：

- 非官方公开 Search API；
- 上游存在 `antiFlag` / Spider Access Denied；
- Cookie/JSON 字段未来可能变化。

---

## 5.3 搜狗图片

选择原因：

- 国内补充源；
- 当前结果页中存在可解析的初始化状态；
- SearXNG 当前实现同样从 `window.__INITIAL_STATE__` 中读取 `searchList.searchList`。

不足：

- 本质仍是页面内部结构；
- DOM/State Schema 变化会影响 Parser；
- 图片 URL 与缩略图在当前统一模型中可能相同。

---

## 5.4 Openverse

Openverse 与前三者性质不同：

```text
Bing/Baidu/Sogou
    -> 通用 Web 图片搜索

Openverse
    -> 开放许可内容索引/API
```

选择原因：

- 有正式公开 API；
- 无需 API Key 即可进行匿名请求；
- 部分结果带 License / License URL；
- 可以为“更关注可复用/授权信息”的 Agent 场景提供补充。

不足：

- 覆盖面不是通用搜索引擎等价物；
- 匿名 API 有 Rate Limit；
- 国内公网可达性不作为 V1 SLA 承诺。

# 6. 为什么当前没有接 360 图片？

普通网页 Search 已经接入 360，但 OpenReach v0.1.0 文搜图没有为了“数量对齐”强行增加 360 Images。

当前原则是：

> **宁可少一个 Provider，也不为了凑渠道数引入未经充分验证、极易变化的图片接口。**

本轮调研中，Bing Images、百度图片、搜狗图片的解析路径都有成熟开源实现可以交叉验证；Openverse 则有正式公开 API。

因此 OpenReach v0.1.0 先将这四路作为可维护的初始集合。

后续如确认 360 图片存在稳定、可持续维护的路径，可直接新增：

```java
So360ImageSearchProvider implements ImageSearchProvider
```

无需修改 API。

# 9. Image Search 与 Read 的组合方式

只拿到图片直链并不是完整 Agent 使用方式。

推荐：

```text
image-search("杭州西湖夜景")
           ↓
ImageSearchItem
           ↓
sourcePageUrl
           ↓
read(sourcePageUrl)
           ↓
获取图片所在网页上下文
```

这样 Agent 可以同时获得：

```text
图片
图片来源
页面正文
引用证据
```

这也是 `sourcePageUrl` 必须成为一等字段的原因。

# 10. Read 当前能力

当前实现：

```text
JDK HttpClient
+ UrlSafetyGuard
+ Redirect Guard
+ Jsoup
+ HtmlContentExtractor
```

| 能力 | 状态 | 说明 |
|---|---:|---|
| HTTP/HTTPS | ✅ | 核心 |
| Redirect | ✅ | 每一跳重新 SSRF 校验 |
| HTML/XHTML | ✅ | 主要目标 |
| Plain Text | ✅ | 基础支持 |
| Charset | ✅ 基础 | Header/meta + GB2312→GB18030 |
| Title/Metadata | ✅ 基础 | title/description/author/time |
| 正文候选评分 | ✅ | 避免只拿小营销块 |
| Links | ✅ | 限量返回 |
| Max Body | ✅ | 防超大响应 |
| Max Content | ✅ | 可截断 |
| SSRF | ✅ 基础 | private/loopback/link-local 等 |
| JS Rendering | ❌ | 后续 Playwright |
| PDF | ❌ | 后续独立 Reader |
| Login/Cookie | ❌ | V1 不做 |
| Browser Action | ❌ | V1 不做 |

# 11. 当前适用场景

适合：

```text
Agent 搜索官网/技术资料
中文通用 Web Search
文搜图 / 插图候选发现
搜索 -> 阅读 -> LLM 总结
图片搜索 -> 来源页阅读
内部 PoC / Agent Tool
低~中频 Web Discovery
```

当前不适合直接承诺：

```text
Google SEO Rank Tracking
高 QPS 商业 Search SLA
严格实时新闻
地图/本地商家
Shopping SERP
Reverse Image Search
版权自动授权
重度 JS/登录网页抓取
```

# 13. 当前能力一句话总结

```text
OpenReach v0.1.0 =
5 路普通网页 Search
+
4 路文搜图 Image Search
+
安全 Web Read
+
统一 Java SPI
```

目标不是一次做到商业 Search Engine，而是先给 Agent 建立一组稳定、可组合、后续可无侵入接入 Serper/SearXNG/Browser 的 Web 基础能力。
